# M1 — BNN prior (dual-purpose: data source + rollout environment)

See `docs/ROADMAP.md` Phase 1 for the *why*.

- [x] Reconciled into `src/anytimeacquisition/priors/bnn.py`, based on
      `archive/src/exit/prior/vectorized_bnn.py` (masked-batch, no external
      deps). Deliberately did **not** carry forward
      `archive/src/exit/prior/bnn.py` / `archive/src/prototype/l2a/prior/{bnn,mlp}.py`
      — that line depends on an external `pfns4hpo` package we don't have as
      a dependency, and its disk-cache key didn't include `x_dim` (a latent
      bug: changing dimensionality without clearing the cache dir would
      silently load the wrong ECDF). Its one genuinely good idea — caching
      the fitted ECDF to disk — is ported, fixed (see below)
- [x] Configurable input dimensionality (`x_dim`) — constructor arg, no
      default assumption baked in; `configs/priors/bnn.yaml` defaults to
      `x_dim: 2` as a placeholder only, flagged there and in
      `docs/OPEN_QUESTIONS.md` #2 pending the medium-dim decision
- [x] Differentiable `evaluate(x)`, ECDF-normalized to `[0, 1]` — ported
      numerically as-is from `vectorized_bnn.py` (searchsorted on
      `raw.detach()` for the bin lookup, differentiable linear interpolation
      for the fractional part)
- [x] Vectorized/batched, **not** built on `vmap` — decided against it, see
      the module docstring in `bnn.py` for the full reasoning: each batch
      element needs its own random depth/width (a stated design
      requirement), which `vmap` can't do without the exact same
      pad-to-`(Lmax,Wmax)`-and-mask trick the manual einsum version already
      uses, so `vmap` would add indirection without adding capability or
      (likely) speed here. `archive/src/exit/prior/environment.py`'s
      `BatchedTaskFamily` *does* use `vmap`, but only works because it
      forces the whole batch to share one architecture — a real capability
      loss, not just a style difference
- [x] Environment-style interface: `reset()` redraws a fresh batch of B
      architectures, `evaluate(x)` is the step/dynamics
- [x] Landed in `src/anytimeacquisition/priors/bnn.py` +
      `configs/priors/bnn.yaml`. Left `dummy.py`/`dummy.yaml` in place
      rather than deleting — still the fixture `tests/test_hydra_config.py`
      and `configs/config.yaml`'s default composition use, and swapping the
      top-level default to `bnn` now would break that smoke pipeline before
      `models/surrogates`, `trainer` etc. are real. `priors=bnn` works as an
      explicit override today
- [x] Tests in `tests/test_bnn_prior.py`: output range, differentiability
      w.r.t. `x`, batch-independence (different `reset()` draws → different
      `y` for the same `x`), episode-sampling shapes, ECDF cache round-trip
      (second instance with a different seed/batch-size loads the cached
      ECDF instead of re-fitting, verified by exact tensor equality + no
      second cache file written)
- [x] `if __name__ == "__main__":` demo (`bnn.py`): evaluate-output range,
      episode shapes, a differentiability check, and a batch-independence
      check, all printed
- [x] **New, beyond the original checklist — ECDF persistence** (per this
      session's ask): fitted ECDF is cached to disk under
      `src/anytimeacquisition/priors/_ecdf_cache/` (gitignored,
      regenerable), keyed by a hash of the *family* hyperparameters
      (`x_dim`, depth/width/init-std ranges, ECDF fitting sample counts) —
      not by instance seed, since the ECDF is a property of the prior
      family, not of one drawn instance. `sample_episode(n_train, n_test)`
      added for M2's PFN-training data generation.
- [x] `plot_1d_environments()` / `plot_2d_environments()` demo plots added
      to `bnn.py` (n_envs/n_random/seed/out_path all adjustable)
- [x] **Fixed after M1 was first marked done — most draws were flat.**
      `init_std` was sampled independent of the drawn `width`; replaced with
      a `crit_range` parameter (`crit = init_std**2 * width`, sampled
      log-uniformly, `init_std` derived from it) so most draws now show real
      structure instead of only the occasional lucky one. Full investigation
      and before/after numbers: `docs/log/2026-08-27-bnn-prior-flat-draws-crit-scaling.md`
- [x] **Compared against PFNs4BO's and ifBO's own BNN priors** (same
      research lineage — see `docs/log/2026-08-27-pfns4bo-bnn-prior-comparison.md`
      and its 2026-08-28 addendum) and aligned with them
      (`docs/log/2026-08-28-align-bnn-prior-with-pfns4bo-ifbo.md`):
  - `depth_range` floor raised `2 -> 8` (neither reference samples below 8;
        a depth-2/3 net is structurally near-incapable of complex output)
  - `sparseness=0.145` (hidden-to-hidden weights only, matching both
        references applying it to `linears[1:-1]`)
  - preactivation noise (every layer) + output noise, both per-instance,
        with an `evaluate(..., noise=False)` escape hatch for M5's
        exploit/explore search
  - fan-in-aware input scaling (`z-score, then / sqrt(x_dim)`), matching
        PFNs4BO's `sample_input()` + `/ sqrt(num_features)`
  - spurious dimensions (`frac_relevant_features=0.7`, matching PFNs4BO
        §5.2's 30% irrelevant) — irrelevant dims' `W_in` row is zeroed per
        instance, verified via exactly-zero gradient in tests
  - `crit_range` generalized to `log_amp_range` (target range for
        `depth * log(crit)`, not `crit` alone) — the depth-range increase
        alone produced visible pure-noise environments at high depth with
        the old fixed `crit_range`, caught by looking at the regenerated
        plots, not by any metric
  - **Not implemented — shelved.** Input warping (PFNs4BO §5.1, both an
        in-prior and a post-hoc-after-prior-fitting version, quoted exactly
        in the 2026-08-27 addendum). `SHELVED` — revisit once we've reached
        real-world testing (i.e. once run against actual, non-synthetic
        hyperparameter search spaces), where its benefit (modeling
        non-uniform input sensitivity) becomes measurable
- [x] **Variable dimensionality — optional, off by default.** Matches
      PFNs4BO's `sample_num_feaetures_get_batch` + `VariableNumFeaturesEncoder`
      (zero-pad beyond the sampled feature count, rescale the active ones):
      `variable_dim_min` (default `None` = current fixed-`x_dim` behavior,
      verified byte-identical). When set, each instance independently
      samples `active_dim` at `reset()` (per-instance, not per-batch like
      PFNs4BO — denser signal per training step given everything else here
      is already per-instance); dims beyond it are zeroed in both `W_in`
      (composed into `relevant_mask`) and the x values `sample_episode`
      returns, and the fan-in scaling in `_raw_forward` divides by
      `sqrt(active_dim)` instead of the fixed `sqrt(x_dim)`. **Not turned on
      anywhere yet** — M2 deliberately trains on one known `x_dim` to keep
      the pipeline simple; the capability exists for before real-world
      benchmarks need one PFN to generalize across dimensionalities. Tests
      cover the disabled-path-is-unchanged claim directly, not just by
      inference.
