# M2 — Frozen PFN checkpoint

See `docs/ROADMAP.md` Phase 2 for the *why*. Depends on M1.

- [x] Ported the PFN transformer from `archive/.../repo/src/model/pfn.py`
      (train-train self-attn / test-train cross-attn only, no TabPFN
      feature-attention, no positional encoding) into
      `src/anytimeacquisition/models/pfn.py`, near-verbatim — see the module
      docstring for the one deliberate deviation from PFNs4BO's own
      reference mask (`generate_D_q_matrix`): we don't let a test token
      attend to itself, matching the design doc's "never to themselves"
      more literally than their implementation does
- [x] **Changed from the original plan — bounded, not full-support, bar
      distribution.** Resolved `docs/OPEN_QUESTIONS.md` #8 this session:
      `src/anytimeacquisition/models/bar_distribution.py` is a bounded
      `BarDistribution` (fixed `[0,1]` borders) on M1's already
      ECDF-normalized output, ported from PFNs4BO's
      `pfns4bo/bar_distribution.py` (NLL, mean, median, variance, mode) plus
      a new `entropy()` method the original doesn't have (closed-form,
      needed for M5). PFNs4BO's actual `FullSupportBarDistribution` +
      adaptive bin borders was the original plan here but deliberately not
      built — see `docs/log/2026-08-28-m2-pfn-and-bar-distribution.md`.
      Differentiability end-to-end confirmed (`tests/test_bar_distribution.py`)
- [x] PFN-only training pipeline: `src/anytimeacquisition/pipelines/train_pfn.py`.
      Fresh `BNNPrior` instance drawn every step, randomized train/test
      split size per step, AdamW + cosine warmup — matches PFNs4BO's own
      training loop (`docs/log/2026-08-27-pfns4bo-bnn-prior-comparison.md`).
      `train_pfn()`/`load_pfn_checkpoint()` save/load a checkpoint
      (gitignored — regenerable in a couple minutes on CPU, not committed
      as a binary artifact)
- [x] **Converted to a Hydra pipeline**, separate from `configs/config.yaml`
      (the EXIT/policy-training composition) since PFN pretraining doesn't
      touch `benchmarks`/the EXIT `trainer` at all:
      `configs/train_pfn.yaml` (defaults: `priors: bnn`,
      `models/surrogates: pfn`, `trainer: pfn_trainer`, `callbacks: mlflow`),
      `configs/models/surrogates/pfn.yaml` (`max_x_dim` interpolated from
      `priors.x_dim` so they can't drift out of sync). `train_pfn.py`'s
      `main()` mirrors `pipelines/train.py`'s provenance + MLflow-logging
      convention exactly.
- [x] **Training loop is a `_target_`-instantiable trainer class**
      (`trainer/pfn_trainer.py`'s `PFNTrainer`), same shape as
      `trainer/dummy.py`'s `DummyTrainer` — not a plain function whose
      hyperparameters get manually unpacked from `cfg` one field at a time
      in `main()`. An earlier version did exactly that (a `_train_loop(...)`
      helper plus a matching explicit `cfg.xxx=...` call) — pure duplication
      of the config schema across three places (YAML, function signature,
      unpacking call) for no actual abstraction benefit, caught in review
      and fixed same-session. `hydra.utils.instantiate(cfg.trainer,
      prior=prior, model=model, bar_dist=bar_dist, seed=cfg.seed, ...)`
      now does the field-matching automatically; `train_pfn()` (the plain
      convenience function tests/notebooks call) builds the same
      `PFNTrainer` from scalar kwargs instead of duplicating the loop.
- [x] **`mixed_precision` (AMP) support**, per your ask, matching ifBO's
      own `train_mixed_precision` flag (also default-off there) but with
      the modern `torch.amp` API rather than the deprecated `torch.cuda.amp`
      alias. CUDA-only — safely no-ops on CPU (verified,
      `tests/test_train_pfn.py`), which is the only path actually
      exercisable in this environment (no CUDA GPU here, local dev
      deliberately CPU-only — `docs/OPEN_QUESTIONS.md` #7). **The CUDA path
      itself is unverified** — correct by inspection against ifBO's
      reference, not tested on real hardware. Validate on the cluster
      before relying on it for a real run.
- [x] **`configs/experiment/`** (Hydra's standard `# @package _global_`
      experiment-config pattern) — `pfn_smoke_xdim2.yaml` and
      `pfn_smoke_xdim1.yaml` replace the two hardcoded smoke-training calls
      that used to live in `train_pfn.py`'s `__main__`. Run via:
      `uv run python -m anytimeacquisition.pipelines.train_pfn experiment=pfn_smoke_xdim2`
- [x] `if __name__ == "__main__":` demos: `models/pfn.py` (forward pass,
      permutation invariance, no-leakage check, no training);
      `models/bar_distribution.py` (NLL/entropy/mean on analytic cases).
      `pipelines/train_pfn.py` is Hydra-only now that it's a real pipeline
      (matches `train.py`) — its "way to interact with it" is
      `experiment=pfn_smoke_xdim1`/`xdim2` runs and the notebook, not a bare
      `python -m` demo
- [x] Re-verified numerically: permutation invariance, no test-test leakage
      — both in `tests/test_pfn.py`, plus a direct gradient-isolation check
      (`d(logits at test point i)/d(x at test point j != i)` is exactly
      zero) that's stronger than a forward-pass equality check alone
- [x] Predictive-entropy-vs-context-size checked in
      `notebooks/pfn_prior_overlay_showcase.ipynb` at `x_dim=1` (not yet at
      the medium-dim target — still unpinned, `docs/OPEN_QUESTIONS.md` #2).
      **Confirmed non-monotonic** (`n_train=2,5,10,20` -> mean entropy
      `-0.619, -0.782, -0.611, -0.645`), same qualitative finding as the
      original prototype's `x_dim=2` run — not an artifact of the
      now-fixed flat-draws bug or an undertrained checkpoint (this run
      converged well). Real, open concern for M5's explore branch — see
      `docs/log/2026-08-28-m2-pfn-and-bar-distribution.md`; re-check again
      once `x_dim` is pinned to the medium-dim target
- [x] Tests (`tests/test_bar_distribution.py`, `tests/test_pfn.py`,
      `tests/test_train_pfn.py`): NLL decreases over a short training run,
      entropy matches the analytic uniform-distribution case exactly,
      checkpoint save/load round-trips
- [x] **New — `notebooks/pfn_prior_overlay_showcase.ipynb`**: trains a
      small `x_dim=1` PFN inline (self-contained, not dependent on the
      gitignored checkpoint file), then plots the prior's true function +
      sampled train data + the PFN's predictive density overlaid on one
      plot, at a few different seeds and context sizes, plus the entropy
      trend above. Executed with outputs committed.
