      `src/anytimeacquisition/search/exploit.py`'s `exploit_search` —

      `src/anytimeacquisition/search/explore.py`'s `explore_search`:
      multistart GD on a candidate `x_explore`, teacher-forced through the
      true BNN instance (`prior.evaluate`, recomputed fresh every step —
      not a self-predicted or post-hoc-patched y), scored by the frozen

      math as `metrics.inc_auc.log_incumbent_stepwise_reward`). Best-so-far
      tracked across every restart/step. Zero-weight instances are flagged
      via `has_signal=False`, not silently searched anyway. **Full design
      history, including a real circularity bug this went through and the

## Design decisions from discussion (2026-08-27)

- **Weight oracle-corrected examples/trajectories by realized inc-AUC
  improvement — decided, with mandatory luck control.** A lightweight,
  RL-free precursor to M5.5's advantage-weighted regression: inject
  trajectory-level signal into the otherwise purely per-step-supervised loss
  by weighting each trajectory's examples by that trajectory's realized
  inc-AUC. Precedent in `archive/src/prototype/l2a/ROADMAP.md` ("weigh each
  sequence by the minimum regret found over T ... encouraging optimization
  on the batch level").

  **Must be weighted relative to a per-instance baseline, never raw
  inc-AUC.** Achievable output range varies wildly by BNN instance (design
  doc §2) — raw weighting would just reward "got an easy instance," not
  "searched well." Concretely: run several rollouts per BNN draw and weight
  relative to that instance's own mean/best (mirrors
  `archive/src/prototype/l2a/ROADMAP.md`'s "horizon-specific baseline" /
  stratified-batching notes, and the same instance-adaptive-control-variate
  reasoning behind the RL value head, §7.2 — this is a cheap version of that
  idea, not a replacement for it). Run a spread/collapse check (same style
  as the exploitation-pull diagnostic) before trusting it in a real training
  run — specifically check it isn't just upweighting trajectories that got
  lucky early, which would reintroduce exploitation-pull one level up.
